Root Access: Magisk vs KernelSU

Posted on May 25, 2026 / 16 min read

Ini adalah penutup dari series Android Rooting. Setelah unlock bootloader (Part 1) dan install custom recovery (Part 2), sekarang kita bahas hal yang paling banyak ditanyakan: root access.

Saya sudah pakai Magisk selama bertahun-tahun, dan baru beberapa bulan lalu coba KernelSU. Ternyata keduanya punya pendekatan yang sangat berbeda, dan pilihan antara keduanya tergantung dari apa yang kamu butuhkan.

Apa Itu Root?

Root adalah akses admin (superuser) ke sistem operasi Android. Dengan root, kamu bisa:

  • Akses dan modifikasi file system level (termasuk /system)
  • Install modules yang mengubah perilaku Android
  • Jalankan backup full system
  • Hapus bloatware yang nggak bisa dihapus biasanya
  • Automasi dengan akses penuh ke perangkat

Tapi root juga berisiko. Satu kesalahan bisa brick device. Makanya penting untuk memahami bagaimana root bekerja, bukan hanya cara install-nya.

Dua Pendekatan Root

Magisk: Systemless Root

Magisk adalah “systemless” root, artinya nggak memodifikasi partition /system secara langsung. Sebagai gantinya, Magisk memodifikasi boot image dan menggunakan Magic Mount untuk mem-mount modifikasi secara virtual.

Cara kerja:

  1. Magisk patch boot image (memodifikasi kernel)
  2. Saat boot, Magisk daemon jalan sebelum Android
  3. Magic Mount membuat virtual overlay di atas /system
  4. Apps melihat /system yang sudah dimodifikasi, tapi file asli tetap utuh

KernelSU: Kernel-Based Root

KernelSU mengambil pendekatan berbeda. Ia memodifikasi kernel secara langsung. KernelSU berjalan di kernel space (bukan user space seperti Magisk), sehingga punya akses yang lebih fundamental.

Cara kerja:

  1. KernelSU patch kernel saat build (atau patch boot image seperti Magisk)
  2. KernelSU module berjalan di kernel space
  3. Root access dikelola langsung oleh kernel
  4. Tidak perlu Magic Mount. Modifikasi dilakukan di level yang lebih rendah

Perbandingan Fitur

AspekMagiskKernelSU
Tipe rootSystemless (user space)Kernel-based (kernel space)

Magisk: Deep Dive

Install Magisk

Langkah detail:

terminal
# 1. Download Magisk APK dari GitHub
# https://github.com/topjohnwu/Magisk/releases

# 2. Extract boot.img dari ROM yang kamu pakai
# (biasanya ada di zip ROM)

# 3. Patch boot.img via Magisk app
# Buka Magisk → Install → Select and Patch a File → pilih boot.img

# 4. Copy patched boot.img ke PC
# File ada di /sdcard/Download/magisk_patched-xxxxx.img

# 5. Flash
adb reboot bootloader
fastboot flash boot magisk_patched-xxxxx.img
fastboot reboot

Magisk Modules

Magisk modules adalah ZIP files yang bisa di-install via TWRP atau Magisk app. Module bisa:

  • Menghapus bloatware (debloater modules)
  • Menambah fitur (ad blockers, sound mods)
  • Mengubah tampilan (themes, fonts)
  • Meningkatkan performa (kernel tweaks)
terminal
# Install module via Magisk app
# Magisk → Modules → Install from storage → pilih ZIP

# Atau via adb
adb push module.zip /sdcard/
# Buka Magisk app → Modules → Install

Magisk Hide & DenyList

Fitur untuk menyembunyikan root dari apps tertentu (banking apps, Google Pay, game anti-cheat):

  • Magisk Hide (deprecated): menyembunyikan root dari semua apps
  • DenyList: daftar apps yang nggak boleh lihat root

Note

Sejak Magisk v24+, Magisk Hide digantikan Zygisk DenyList. Zygisk adalah replacement Zygote yang memungkinkan modifikasi process spawning.

# Build kernel
# Flash via fastboot

KernelSU Modules

KernelSU menggunakan KMI (Kernel Module Interface): modules berjalan di kernel space, bukan user space. Ini artinya:

  • Modules bisa melakukan hal yang Magisk modules nggak bisa
  • Lebih dekat ke hardware
  • Potensi lebih powerful, tapi juga lebih berisiko

Kenapa KernelSU Lebih Baru?

KernelSU lahir dari kebutuhan akan root yang:

  1. Lebih aman: berjalan di kernel space, lebih sulit di-detek
  2. Lebih powerful: bisa modifikasi kernel langsung
  3. Lebih clean: nggak perlu Magic Mount atau Zygisk
  4. Lebih modern: designed untuk Android 12+

Tapi trade-off-nya: device support lebih terbatas, karena KernelSU harus compatible dengan kernel device kamu.

Mana yang Harus Dipilih?

Rekomendasi Saya

Keamanan Root

Risiko

Root membuka akses penuh ke sistem. Ini berarti:

RisikoPenjelasanMitigasi
MalwareMalware bisa mendapat root accessHanya install apps dari sumber trusted
BrickModifikasi yang salah bisa matikan deviceSelalu backup sebelum modifikasi
GaransiBeberapa pabrikan void garansi saat rootCek kebijakan pabrikan
Security patchRoot bisa delay security updateGunakan ROM yang masih aktif di-update
Data theftRoot access = akses penuh ke semua dataJangan root device yang berisi data sensitif

Best Practices

  1. Jangan root daily driver tanpa alasan: root hanya jika kamu benar-benar butuh
  2. Gunakan DenyList untuk banking apps: jangan biarkan root terlihat oleh apps sensitif
  3. Update security patch: jangan karena root kamu skip update keamanan
  4. Backup rutin: Nandroid backup minimal seminggu sekali
  5. Hanya install modules dari trusted source: XDA, GitHub, atau repository resmi

Komunitas & Perspektif

Magisk Community

Magisk adalah “industry standard” untuk Android root. Dikembangkan oleh John Wu (topjohnwu), yang sekarang juga bekerja di Google (ironis, tapi menunjukkan kualitas kode Magisk).

KernelSU Community

KernelSU masih relatif baru, tapi berkembang pesat. Community-nya lebih teknikal karenabutuh pemahaman tentang kernel.

Perspektif Developer

“Root itu bukan soal ‘hacking’. Ini soal ownership. Kamu beli HP, kamu harusnya punya kontrol penuh atasnya. Tapi dengan kontrol penuh datang tanggung jawab penuh juga.”

Tips dari Pengalaman Saya

  1. Mulai dengan Magisk: lebih mudah, lebih banyak dokumentasi, lebih banyak modules
  2. Coba KernelSU setelah nyaman dengan Magisk: kalau kamu merasa butuh lebih, KernelSU bisa jadi next step
  3. Jangan install terlalu banyak modules: semakin banyak module, semakin besar potensi konflik
  4. Test di device secondary: jangan langsung root daily driver
  5. Keep TWRP updated: untuk backup darurat

Troubleshooting

Magisk: “Magisk not installed”

terminal
# Cek apakah boot image sudah ter-patch
fastboot flash boot magisk_patched-xxxxx.img
fastboot reboot

# Jika masih gagal, coba flash ulang
# Pastikan patch boot.img dari ROM yang SAMA dengan yang ter-install

KernelSU: Module tidak work

  • Pastikan module compatible dengan kernel version kamu
  • Cek KernelSU Manager → Modules → lihat status module
  • Disable module dan reboot untuk test

Root hilang setelah OTA update

OTA update mengembalikan boot image ke versi stock. Solusi:

terminal
# Magisk:
# 1. Download OTA tapi JANGAN install
# 2. Patch boot.img dari OTA zip
# 3. Flash patched boot.img
# 4. Install OTA (Magisk akan survive)

# KernelSU:
# 1. Flash KernelSU kernel ulang setelah OTA
# 2. Atau gunakan custom ROM yang support OTA + root

Banking apps deteksi root

terminal
# Magisk: gunakan DenyList
# Magisk → Settings → Configure DenyList → tambah banking app

# KernelSU: sudah built-in, tapi pastikan kamu pakai
# kernel yang compatible

Kesimpulan

Root Android memberikan kontrol penuh atas device kamu. Magisk adalah pilihan yang lebih mature dan luas support-nya, sementara KernelSU menawarkan pendekatan yang lebih modern dan powerful untuk device yang compatible.

Pilihan ada di tangan kamu. Yang terpenting adalah memahami risikonya dan selalu backup sebelum modifikasi.
