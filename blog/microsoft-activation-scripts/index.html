Microsoft Activation Scripts (MAS): Apa Itu, Bagaimana Cara Kerjanya, dan Apa yang Perlu Diketahui

Posted on August 20, 2026 / 17 min read

Pengenalan

Microsoft Activation Scripts (MAS) adalah tool aktivasi Windows dan Office yang sudah cukup lama beredar di komunitas tech. Tool ini menarik perhatian karena menjadi salah satu project open-source dengan jumlah stars tertinggi di GitHub untuk kategori aktivasi.

Artikel ini akan membahas MAS dari berbagai sudut pandang: bagaimana cara kerjanya, apa yang dikatakan berbagai pihak tentang tool ini, serta aspek keamanan dan legalitas yang perlu dipahami.

Apa Itu MAS?

MAS (Microsoft Activation Scripts) adalah kumpulan script aktivasi Windows dan Office yang dikembangkan oleh komunitas. Tool ini bukan produk Microsoft - ini adalah hal penting yang perlu dipahami sejak awal.

Beberapa fakta dasar tentang MAS:

  • Tersedia di GitHub dengan lebih dari 188k stars dan 17.9k forks
  • Ditulis dalam batch script dan PowerShell, bukan binary executable
  • Versi terbaru: 3.12 (rilis 4 Juli 2026) - menandai 8 tahun berjalannya project ini
  • Tersedia di beberapa mirror: GitHub, Azure DevOps, dan self-hosted Git

Karena bersifat open-source, kode sumber MAS bisa di-review oleh siapa saja. Ini menjadi salah satu alasan mengapa project ini mendapat perhatian besar - pengguna bisa melihat langsung apa yang dilakukan script-nya.

Metode Aktivasi

MAS menyediakan empat metode aktivasi utama, masing-masing dengan karakteristik teknis yang berbeda.

1. HWID (Hardware ID)

HWID adalah metode untuk aktivasi Windows 10 dan 11. Metode ini memberikan “digital license-style activation” yang diikat ke hardware ID sistem.

Cara kerja: Metode ini menggunakan Installation ID dari product key yang valid untuk menghasilkan GenuineTicket yang dikirim ke server Microsoft. Server kemudian mengeluarkan digital license yang diikat ke hardware spesifik.

Sejarah singkat: Metode pertama HWID dimulai dari musim panas 2018 hingga September 2023, memanfaatkan proses upgrade resmi dari Windows 7 ke Windows 10. Microsoft memblokir metode ini di sisi server untuk aktivasi baru, tapi license yang sudah terbentuk tetap valid.

Karakteristik:

  • Aktivasi permanen sampai motherboard diganti
  • Bisa di-link ke akun Microsoft
  • License tersimpan di server Microsoft, reinstall dengan edisi sama otomatis teraktivasi
  • Diperlukan koneksi internet untuk aktivasi pertama

Yang perlu diperhatikan: HWID tidak mendukung Windows Server. Script secara eksplisit menolak HWID untuk edisi Server.

2. TSforge

TSforge adalah metode yang lebih fleksibel karena mendukung hampir semua produk Windows dan Office. Metode ini bekerja dengan memanipulasi data di physical store dan token store SPP (Software Protection Platform).

Tiga varian TSforge:

VarianKoneksi InternetMasa AktifCatatan
ZeroCIDTidak diperlukanPermanent (sampai reinstall/upgrade)Offline
StaticCIDDiperlukanPermanent (sampai reinstall/upgrade)Untuk Windows 11 build 26100+
KMS4kTidak diperlukan4000+ tahunOffline, persist through hardware changes

Yang menarik dari TSforge:

  • Bisa mengaktifkan Windows ESU (Extended Security Updates)
  • Mendukung Windows dari Vista hingga Windows 11
  • Mendukung Office 2013 sampai 2024

3. Ohook

Ohook adalah metode khusus untuk Office. Yang unik dari Ohook adalah ia tidak memodifikasi file sistem Windows - ia bekerja dengan menempatkan custom SPPC.dll di folder Office.

Cara kerja: Saat Office menanyakan status aktivasi, ia memanggil C:\Windows\System32\sppc.dll. Ohook menempatkan versi custom dari file ini di folder Office yang selalu mengembalikan pesan bahwa Office sudah teraktivasi.

Dukungan:

  • Office 2010 sampai 2024
  • Office 365 (dengan catatan: fitur server-side seperti storage 1TB OneDrive tidak tersedia)
  • Office UWP tidak didukung

4. Online KMS

Online KMS memberikan masa aktif 180 hari, tapi dengan auto-renewal task bisa diperpanjang secara otomatis. Metode ini memerlukan koneksi internet.

Siklus aktivasi KMS: aktivasi awal valid 180 hari, lalu task auto-renewal menjalankan aktivasi ulang setiap ~160 hari sehingga masa aktif selalu ter-refresh sebelum habis.

Yang perlu dipahami: KMS (Key Management Service) adalah teknologi aktivasi resmi Microsoft untuk organisasi. Namun, penggunaan KMS publik yang tidak authorized berbeda dari deployment KMS resmi sebuah organisasi.

Perspektif Berbeda

Masalah aktivasi selalu menjadi topik yang beragam. Berikut beberapa sudut pandang dari berbagai pihak tentang MAS.

BleepingComputer (Maret 2023)

BleepingComputer menerbitkan artikel menarik tentang kasus di mana seorang Microsoft support engineer menggunakan MAS untuk mengaktifkan Windows seorang pelanggan yang sudah membeli license resmi tapi gagal aktivasi.

“I can’t believe it. My official Microsoft Store Windows 10 Pro key wouldn’t activate. Support couldn’t help me yesterday… Today it was elevated. Official Microsoft support (not a scam) logged in with Quick Assist and ran a command to activate windows… BRO IT’S A CRACK. NO CAP.”

  • Wesley Pyburn, pelanggan Microsoft

Menurut BleepingComputer, ini bukan pertama kalinya Microsoft support menggunakan tools seperti ini:

“This is the second time someone reported here that it’s being used by Microsoft support agents. It’s not official and not legal.”

  • WindowsAddict, Massgrave staff

Microsoft sendiri merespons:

“We strive to provide best-in-class support for our customers. The technique you described would be against our policy. We are investigating this occurrence and will take appropriate steps to ensure proper procedures are followed.”

  • Juru bicara Microsoft kepada BleepingComputer

Artikel lengkap: Microsoft support ‘cracks’ Windows for customer after activation fails (opens in a new tab)

Up North Media (Oktober 2025)

Up North Media menerbitkan analisis tentang supply chain risk yang cukup menarik. Mereka mencatat bahwa MAS memiliki lebih dari 1 juta pengguna aktif, namun update mechanism-nya tidak memiliki verifikasi kriptografi.

Analisis mereka tentang potensi risiko:

“The critical takeaway isn’t that MAS is malicious today, but that its technical design makes weaponization trivial tomorrow.”

Mereka juga menyoroti beberapa aspek teknis:

“The update mechanism lacks cryptographic verification… creates an attractive target for well-funded threat actors.”

Analisis lengkap: Understanding the Supply Chain Risks in Windows Activation Tools (opens in a new tab)

NotebookCheck (Januari 2026)

NotebookCheck membahas kasus di mana Microsoft Defender sempat memblokir MAS. Temuan mereka cukup menarik - setelah pengujian, mereka tidak bisa mereplikasi error tersebut:

“We suspect… the detection logic might actually be working exactly as intended… a DNS spoofing scenario.”

Artinya, bukan Defender yang salah, tapi mungkin ada DNS spoofing yang mengarahkan pengguna ke versi palsu.

GitHub Release v3.12 (Juli 2026)

Tim developer MAS sendiri memberikan beberapa update di versi terbaru:

“Hardened the script against certain types of vulnerabilities.”

Release v3.12 juga menandai 8 tahun berjalannya project MAS.

GitHub, Microsoft, dan MAS

Pertanyaan yang sering muncul: GitHub dimiliki oleh Microsoft (diakuisisi pada tahun 2018), lalu kenapa MAS tidak dihapus dari platform ini?

Konteks DMCA di GitHub

GitHub memiliki kebijakan DMCA (Digital Millennium Copyright Act) yang mengatur penghapusan konten yang melanggar hak cipta. Proses DMCA di GitHub melibatkan:

  1. Pemilik hak cipta mengirim takedown notice
  2. GitHub mengirim notifikasi ke pemilik repository
  3. Pemilik repository diberi kesempatan untuk merespons atau mengubah konten
  4. Jika tidak ada respons, repository dapat dihapus

Yang menarik, GitHub membedakan antara copyright infringement biasa dan anti-circumvention claims (klaim tentang pembypassan teknologi proteksi). Untuk klaim anti-circumvention, GitHub melakukan review yang lebih ketat dengan bantuan ahli teknis dan hukum.

Microsoft Sudah Pernah Kirim DMCA

Bukti bahwa Microsoft aktif menggunakan DMCA di GitHub bisa dilihat dari repository github/dmca (opens in a new tab) . Pada Mei 2026, Microsoft mengirim DMCA takedown untuk repository yang berisi source code Minecraft yang bocor - menghapus 1349 repositories.

Namun, DMCA ini bukan tentang activation tools - ini tentang source code yang bocor.

Kasus KMS Activator Sebelumnya

Pada tahun 2019, Microsoft mengirim DMCA takedown untuk repository CHEF-KOCH/KMS-activator. Namun, pemilik repository mengajukan counter-notice dengan argumen menarik:

“KMS is a genuine activation method provided by Microsoft for volume licensing customers… The KMS emulators are mimic the KMS server/client communications, and provide a clean activation for the supported KMS clients, without altering or hacking any system files integrity.”

Counter-notice ini tersimpan di GitHub DMCA repository (opens in a new tab) .

Pertanyaan yang Sering Diajukan

Di GitHub issue #550 (opens in a new tab) pada repository MAS, seseorang menanyakan:

“As far as I know, GitHub has been acquired by Microsoft, and it is now operating under DMCA policy. Why has this project remained unbanned on GitHub for so long?”

Beberapa tanggapan di issue tersebut:

“The existence of MAS singlehandedly pushes Windows’ market share forward by a significant margin and it’s against Microsoft’s interests to remove the repository from GitHub considering most of their users cannot afford paying for Windows licenses.”

Ada juga yang menunjuk fakta bahwa Microsoft support sendiri pernah menggunakan MAS:

“Also, they need it to fix customer issues related to activation.”

Kenapa MAS Mungkin Tidak Dihapus?

Ada beberapa kemungkinan yang bisa dipertimbangkan:

  1. Kebijakan DMCA GitHub: GitHub memiliki proses yang ketat untuk anti-circumvention claims dan cenderung “err on the side of the developer” saat klaim ambigu

  2. Sifat open-source: MAS adalah script batch/PowerShell, bukan binary executable. Sulit untuk membuktikan bahwa kode ini melanggar hak cipta Microsoft secara langsung

  3. KMS sebagai teknologi resmi: Seperti yang diargumentasikan dalam counter-notice 2019, KMS adalah teknologi resmi Microsoft. Emulasi KMS berada di area abu-abu

  4. Microsoft sendiri menggunakan MAS: Seperti yang dilaporkan BleepingComputer, Microsoft support pernah menggunakan MAS untuk membantu pelanggan

  5. Strategi bisnis: Beberapa pihak berpendapat bahwa Windows yang “teraktivasi” (meskipun tidak melalui jalur resmi) tetap lebih baik untuk Microsoft daripada pengguna yang beralih ke Linux

Namun, ini semua adalah spekulasi. Microsoft tidak pernah memberikan pernyataan resmi tentang kenapa MAS tetap ada di GitHub.

Keamanan

Aspek keamanan MAS bisa dilihat dari dua sisi.

Sisi Positif

  • Open-source: Kode bisa di-review oleh siapa saja
  • Transparan: Tidak ada binary executable yang harus dipercaya tanpa verifikasi
  • Komunitas aktif: 188k stars di GitHub, forum Discord dan Reddit yang aktif
  • Update berkala: Tim developer aktif memperbarui metode

Sisi yang Perlu Diperhatikan

  • Administrator privileges: Script berjalan dengan hak akses penuh
  • Supply chain risk: Mirror atau fork bisa dimodifikasi oleh pihak ketiga
  • Update mechanism: Tidak ada verifikasi kriptografi untuk update
  • Modifikasi registry: Script melakukan beberapa modifikasi registry
  • Ketergantungan pada sumber: Pengguna harus memastikan download dari sumber yang benar

Catatan tentang Antivirus

Kasus yang dibahas NotebookCheck menunjukkan kompleksitas masalah ini. Microsoft Defender pernah memblokir MAS, namun setelah pengujian, masalahnya ternyata bukan false positive - tapi kemungkinan DNS spoofing yang mengarahkan pengguna ke versi palsu.

Beberapa antivirus pihak ketiga mungkin memberikan peringatan karena topik aktivasi memang sensitif. Namun, bukan berarti setiap peringatan harus diabaikan.

Legalitas

Aspek legalitas MAS adalah topik yang perlu dipahami dengan jelas.

Secara teknis:

  • MAS bukan aktivasi resmi dari Microsoft
  • Activated state ≠ genuine license
  • Microsoft membedakan antara “activation” dan “validation”

Apa artinya ini:

  • Microsoft bisa saja melakukan perubahan server-side kapan saja yang mempengaruhi metode aktivasi
  • License yang dihasilkan MAS tidak memiliki jaminan seperti license resmi
  • Untuk penggunaan bisnis, risiko audit tetap ada

KMS vs Unauthorized KMS: Penting untuk memahami bahwa KMS adalah teknologi resmi Microsoft untuk organisasi. Deployment KMS yang sah menggunakan authorized KMS host dengan volume-license host key. Penggunaan KMS publik yang tidak authorized adalah praktik yang berbeda.

Konteks hukum: Aspek legalitas bisa berbeda di setiap yurisdiksi, tergantung pada bagaimana software diperoleh, apakah ada hak dasar (underlying entitlement), dan konteks penggunaannya (personal, edukasi, atau komersial).

Kesimpulan

MAS adalah project open-source yang sudah ada cukup lama dan memiliki komunitas yang besar. Secara teknis, tool ini memiliki kapabilitas yang signifikan dalam mengaktivasi Windows dan Office.

Namun, ada beberapa hal yang perlu dipahami:

  1. Activation ≠ License: Aktivasi tidak membuktikan bahwa software diperoleh secara sah
  2. Open-source bukan jaminan keamanan: Kode bisa di-review, tapi supply chain risk tetap ada
  3. Berbagai perspektif: Dari yang melihat ini sebagai tools transparan hingga yang menyoroti risiko keamanan
  4. Konteks legal yang kompleks: Berbeda di setiap yurisdiksi dan situasi
  5. Microsoft dan GitHub: Ada dinamika menarik antara kebijakan DMCA, open-source, dan kepentingan bisnis

Keputusan untuk menggunakan atau tidak menggunakan MAS adalah pertimbangan pribadi. Yang penting adalah memahami apa yang dilakukan tool ini, risiko yang ada, dan konteks di sekitarnya.
